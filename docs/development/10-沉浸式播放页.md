## 0. 结论摘要（先看这段）

**泛音不是「从零做沉浸式」，而是「已有一个可用的沉浸式歌词舞台，缺可插拔与侧栏」。**

在第三～七阶段，我们已经在 `src/renderer/components/layout/ImmersiveLyric/index.vue`（750 行）
做出一套能用的沉浸式视图：全屏遮罩、封面模糊背景 + 不透明兜底层 + 暗幕、行级状态
（active/prev/next）、错位与轻微旋转、逐字/整句两种填充推进、进出场动画、
`prefers-reduced-motion` 降级、底部进度条 + 上一首/播放/下一首 + Esc 退出。

对照 Folia 的五个概念，现状是：

| Folia 概念 | 泛音现状 | 差距大小 |
|---|---|---|
| 统一歌词数据契约 | **已有**（`core/immersiveLyric/timeline.ts` 的纯数据时间轴） | 小：字段比 Folia 少（无 `endTime`/`songPart`/`renderHints`） |
| 歌词解析与时间轴同步 | **已有**（LRC/lxlrc 解析 + 二分查找 + 纯时间函数填充） | 中：只认 LRC 家族，不认 yrc/qrc/krc/ttml/vtt |
| 沉浸式歌词舞台 | **已有**（`ImmersiveLyric/index.vue`） | 中：单模式写死、无频谱、无侧栏 |
| 可插拔视觉模式 | **没有**（只有一套写死的样式） | **大：这是 L0 判定的核心缺口** |
| 播放控制与歌单侧边面板 | **部分**（底部三个按钮 + 进度条；无音量、无播放模式、无队列面板、无歌词菜单） | 大 |

一句话建议：**不要把「歌单界面」整体改造成沉浸页，而是把已有的 `ImmersiveLyric` 升级成
「可插拔舞台」，再把 `PlayDetail` 里现成的能力（歌词菜单 / AI 工具 / 评论）以侧栏形式搬进去。**
理由见 §3.5 与 §5。

### 2.3 HTMLAudioElement 由谁管理

**`src/renderer/plugins/player/index.ts`（19.4 KB）是唯一的音频实例持有者。**

- `createAudio()`：`new window.Audio()`（**单例，且不进 DOM**，所以选择器查不到；`preload='auto'`、`crossOrigin='anonymous'`）
- 资源与播控：`setResource(src)` / `setPlay()` / `setPause()` / `setStop()` / `isEmpty()`
- 时间与时长：`getCurrentTime()` / `setCurrentTime(t)` / `getDuration()`
- 音量与设备：`setVolume` / `setMute` / `setMediaDeviceId`（`setSinkId`）/ `getMute`
- 倍速与变调：`setPlaybackRate` / `setPreservesPitch` / `setPitchShifter`
- 事件注册（**都返回取消函数**）：`onPlaying` / `onPause` / `onEnded` / `onError` / `onLoadeddata` / `onLoadstart` / `onCanplay` / `onEmptied` / `onTimeupdate` / `onWaiting` / `onVisibilityChange`
- **Web Audio 图已经建好了**（`initAdvancedAudioFeatures`）：
  `mediaSource → analyser → biquad(10 段) → pitchShifter(AudioWorklet) → convolver/panner/gain → destination`，
  并导出 `getAnalyser()`（`fftSize=256`）、`getAudioContext()`、`getBiquadFilter()`、`setConvolver()`。
  **→ L4 想要的 `audioPower` / `audioBands` / 频谱，输入已经存在，不需要新建 AudioContext。**

现成的消费者示例：`src/renderer/components/common/AudioVisualizer.vue`（`<canvas>` + `analyser.getByteFrequencyData` + rAF，挂在 `PlayDetail/index.vue:29`，受 `player.audioVisualization` 开关控制）。

### 2.4 歌词：代码、获取接口、解析器

**已存在三层，且层次清晰：**

```
① 获取层（要网络/要文件）
   core/music/index.ts        getLyricInfo()      ← 按 musicInfo 类型分发（在线/本地/下载）
   core/music/online.ts       getLyricInfo()      (:83)
   core/music/utils.ts        handleGetOnlineLyricInfo()  (:470 附近)
                              getOnlineOtherSourceLyricInfo() (:430，换源重试)
                              → musicSdk[source].getLyric()
   core/music/local.ts        getLyricInfo()      (:133，同目录 .lrc + 内嵌 rawlrcInfo)
   utils/ipc.ts               getLyricRaw(musicInfo) (:711，主进程读文件)

② 解析层（两套并存）
   A. 旧：common/utils/lyric-font-player/{index,line-player,font-player,utils}.js
      —— 解析 + DOM 写入耦合（line-player.js 里直接 rAF 驱动 DOM 节点），
         产物是 store 里的 lines，供 LyricPlayer.vue（滚动歌词）与桌面歌词用。
         驱动方：core/lyric.ts（init/setLyric/play/pause/stop/setLyricOffset）
   B. 新：core/immersiveLyric/timeline.ts（283 行，纯数据，无 DOM）
         buildLyricTimeline({ lrc, lxlrc, tlrc }) → { lines, offset, hasWordTiming, source }
         ImmersiveLyricLine { time, text, words: ImmersiveLyricWord[]|null, translation }
         findActiveLineIndex(lines, ms)   ← 二分
         getWordState(word, ms)           ← 'done' | 'active' | 'todo'
       core/immersiveLyric/fill.ts     getWordFill / getLineFill  ← 纯时间函数（无缓动、无计时器）

③ 呈现层
   components/layout/PlayDetail/LyricPlayer.vue   （滚动歌词，右键出 LyricMenu）
   components/layout/ImmersiveLyric/index.vue     （沉浸舞台，见 §2.6）
```

**歌词数据契约（这是「统一歌词数据契约」在泛音的现状）**

`src/common/types/music.d.ts:95`：

```ts
interface LyricInfo {
  lyric: string          // 正文（LRC）
  tlyric?: string | null // 翻译
  rlyric?: string | null // 罗马音
  lxlyric?: string | null// 逐字（lxlrc，`<start,duration>` 毫秒、相对行首）
}
```

播放器侧另存 `rawlrc`（`store/player/state.ts:10`，本地/原始歌词）。这四路 + `rawlrc`
就是泛音目前的全部歌词形态；**没有 `endTime`、没有 `songPart`、没有 `renderHints`、
没有 `alternateTexts`、没有 `wordSegments`**。

时间单位与接受范围（`timeline.ts` 顶部注释，已由 41 条单测锁定）：
对外一律 **ms**，已叠加 `[offset:]`；`[mm:ss.xx]` 判厘秒还是毫秒按**整份文件**统一；
时间戳必须**整段**匹配 `^\d{1,3}(?::\d{1,3}){0,2}\.\d{1,3}$`，畸形标记整条作废。

**「歌词搜索」这件事必须说清**：泛音**没有**独立的「歌词搜索接口」。歌词只能来自
`getLyricInfo` 的三条既有路径（内置平台接口 / 用户自定义源 / 本地文件）。
Folia 的 `GET http://127.0.0.1:32109/v1/lyric` 是**导出当前正在播放歌词的只读本机接口**
（顶层 `offset`；无歌词返回 `null`），**不是**搜索接口 —— 不得当作歌词源接入，也不得据此
推断泛音需要"歌词搜索"。（详见 §6.3）

### 2.6 当前 UI 状态管理 / 样式体系 / 动画技术

- **状态**：模块级 `reactive/ref/computed`（统一从 `@common/utils/vueTools` 导入），**没有 Pinia/Vuex**。
  跨模块通信靠事件总线 `window.app_event`（定义 `src/renderer/event/appEvent.ts`，
  与播放相关的事件名：`musicToggled` / `setProgress` / `setVolume` / `setPlaybackRate` /
  `playerPlaying` / `playerPause` / `playerEnded` / `playerError` / `playerLoadstart` /
  `playerCanplay` / `playerEmptied` / `playerWaiting` / `playerDeviceChanged` /
  `lyricUpdated` / `lyricOffsetUpdate` / `lyricLinePlay(text, line)`）。
- **样式**：Less + **CSS Modules**（`<style lang="less" module>`，类名哈希化，所以自动化断言
  只能用 `[data-state=…]` / `[aria-label=…]` 这类稳定钩子，不能靠类名）。
  主题走 CSS 变量（`--color-primary` / `--color-app-background` / `--background-image` …），
  在 `index.html` 里由 `window.setTheme()` 注入；`variables.less` 提供 `@transition-normal: .4s ease`。
  主题是**预设**（`src/common/theme/index.json` + `setting['theme.id'] / lightId / darkId`），
  **不支持自定义主题导入**。
- **动画**：三条路都在用 —— ① `<TransitionGroup>` + CSS 类（沉浸视图）；
  ② CSS `@keyframes`（`immersiveLineIn/Out`）；③ `animate.less`（animate.css 克隆，`animated fadeIn` 等）。
  ⚠️ 沉浸视图**刻意不用** animate.css：它的关键帧写了 `transform`，会覆盖行级错位/旋转，
  且默认时长 1s（`ImmersiveLyric/index.vue:39-40` 有明确注释）。
- **降级**：`@media (prefers-reduced-motion: reduce)` 已实现，去掉位移/旋转/进出场但**保留状态信息**；
  另用 `isolation: isolate` 保证 reduced-motion 下 `.line` 的层叠上下文不丢（色块不被背景暗幕盖住）。

## 3. Folia 五概念逐项评估

> 评估口径：**只借鉴公开文档描述的交互与架构，不复用其源码/资源**（依据见 §6）。

### 3.1 统一歌词数据契约

| 维度 | 内容 |
|---|---|
| Folia 的做法 | `Line { words[], startTime, endTime, fullText, translation?, romanization?, alternateTexts?, renderHints?, isChorus?, songPart?, blockIndex?, wordSegments? }`；`folium.lyrics.parse(track)` 统一吃 `{format,text,translationText?,romanizationText?}`，支持 `lrc / enhanced-lrc / yrc / qrc / krc / ttml / vtt / awlrc`；解析在 **worker** 里跑 |
| 泛音现状 | `ImmersiveLyricLine { time, text, words: {text,start,duration}[]|null, translation }`；`source: 'none'\|'lrc'\|'lxlrc'`；无 `endTime`（行结束时间靠"下一行 time"或 `maxRateMs=4000` 兜底）、无 `songPart`/`renderHints`/`alternateTexts`/`wordSegments` |
| 可复用 | `core/immersiveLyric/timeline.ts` 整体（纯函数、零依赖、41 条单测覆盖）；`fill.ts` |
| 需新增/调整 | ① `ImmersiveLyricLine` 增 `endTime`（由下一行 time 推导，末行用 `min(duration, maxRateMs)`）；② 增 `songPart`（主歌/副歌/桥段）——**只能从歌词文本里的标记推导，不能凭空造**；③ 若要接 `yrc/qrc/krc/ttml`，需要**新增独立解析器**（现有 LRC 解析器不认这些），且必须显式声明格式，不嗅探 |
| 与播放状态集成 | 不需要播放状态，纯 `musicInfo.lrc/lxlrc/tlrc` → 时间轴。已经是 `computed`，天然跟随切歌 |

## 4. 现有实现的具体差距清单（可直接转 L1 ticket）

**舞台层**
1. 无语音量控制、无播放模式（循环/单曲/随机）切换
2. 无队列侧栏，无法在沉浸页里跳歌
3. 歌词行不可点击跳转（Folia 有 `onLyricLineSeek`）
4. 无歌词来源切换（要退回 `PlayDetail` 右键菜单）
5. 无视觉模式切换（只有一套写死的样式）
6. 无频谱/律动输入（`getAnalyser()` 已有，但沉浸页没用）
7. 无界面自动隐藏（Folia 有 `hidePlayerChrome` / 自动隐藏控制栏）
8. 无设置项：`immersive.*` 一个都没有，i18n 只有 3 个键（`immersive_lyric__open/close/no_lyric`）
9. 键盘只有 Esc

**数据层**
10. 行无 `endTime`（靠下一行或 4000ms 兜底）
11. 无 `songPart`（主歌/副歌标记）
12. 不支持 yrc/qrc/krc/ttml/vtt（只有 LRC 家族 + lxlrc）
13. 无"最佳歌词自动匹配"（Folia 会跨源比选；泛音只按当前源取，失败才换源）

**架构层**
14. 时钟逻辑长在组件里（rAF + heartbeat + 事件订阅 ~120 行），多模式复用会复制粘贴
15. 无模式注册表（`registry`）

> 注意：**10–13 属于"要不要做"的产品决策，14–15 属于"必须先做"的架构准备。**
> L1 建议只做 14/15 + 8，其余按 L2–L4 排。

### 6.2 判断与执行口径

1. **AGPL 与我们同族**（泛音也是 AGPL-3.0），法理上"复制 + 保留许可与署名"是可行的；
   **但对方 README 额外写了"非商业使用"限制**，这与 AGPL 授予的商业使用自由冲突，属于
   **附加限制**。对一个公开分发二进制、还挂着 GitHub Release 的项目，纠缠这一点的成本
   远高于自己写。
2. **技术上也复制不了**：Folia 是 **React 19 + Vite + Framer Motion + Tailwind**，泛音是
   **Vue 3 + webpack 5 + Less/CSS Modules**。13 个模式的实现全部依赖 `framer-motion` 的
   `MotionValue`（`VisualizerSharedProps.currentTime` 就是 `MotionValue<number>`），
   搬过来等于引入一整套 React 运行时。
3. **因此本项目的口径（与本报告的执行标准）**：

   | 允许 | 禁止 |
   |---|---|
   | 阅读其**公开文档**（guide / technical.md / mods/README.md）描述的**交互与架构** | 复制 `src/components/visualizer/**` 的源码 |
   | 借鉴**接口形状**（注册表字段划分、行数据字段语义、共享上下文包含哪些量），用 Vue 与我们自己的类型重写、重新命名 | 复制 `src/utils/lyrics/**` 的解析器 |
   | 借鉴**视觉方向**（"流光/云阶"这类风格描述），自行实现 | 复制 `img/**` 预览图、`public/icon.svg`、任何截图 |
   | 使用系统字体栈 | 引入 Folia 未打包但源码里引用的任何第三方字体文件 |
   | 若将来确需用其代码（例如某个数学函数），必须**单独提交许可评估**、在 `NOTICE` 署名、整仓保持 AGPL，并接受"非商业"争议 | 无评估地粘贴 |

4. **不做的事**：不使用 Folia 的名称、图标作为我们功能的标识（延续既有红线：不用 Folia 商标）。

### 6.3 一条必须澄清的误读（用户明确点名）

> **Folia 的「本机只读歌词 API」不是通用歌词搜索接口。**

事实：`GET http://127.0.0.1:32109/v1/lyric`（`docs/technical.md` 的「歌词接口」段）
在 Electron 端开启"连接与集成"后，**仅在回环地址**提供，返回**当前正在播放**那首歌的精简歌词 JSON，
顶层带用户设置的 `offset`（毫秒），当前没有歌词时返回 `null`。

它的性质是 **"把本机当前歌词导出给外部程序"的只读出口**（供 Quickshell 插件、Stage API、
OBS 之类消费），**不接受任何查询参数、不按歌名搜索、不返回候选列表、不落盘**。

因此：
- 泛音**不应**把它当歌词源接入，也**不应**因为"Folia 有歌词 API"就推断"我们也需要一个歌词搜索接口"；
- 泛音的歌词来源仍只有既有三条：内置平台接口（`musicSdk[src].getLyric`）、
  用户自定义源、本地文件（同目录 `.lrc` / 内嵌标签）；
- 如果 L3 之后想做"对外导出当前歌词"（等价物），那是**另一个功能**，与搜索无关，
  且要单独评估安全面（本机端口暴露）。

## 7. 风险汇总与统一测试方法

| 风险 | 等级 | 说明与对策 |
|---|---|---|
| 双时钟 / 时间轴漂移 | **高** | 硬约束：舞台外壳是唯一时钟；模式只收 `nowMs`；禁止模式内 `requestAnimationFrame` 读 audio |
| 用 `isPlay` 当播放真相 | **高** | 已验证会出错（历史故障）。一律用 audio 元素事件 + `getCurrentTime()` |
| 无音频设备导致"看起来没在播" | **高** | 验收时必须区分「时间轴在推进」与「真的出声」；出声标 BLOCKED |
| 遮罩层透底 / 闪白 | 中 | 兜底层必须**不透明**（第四阶段教训）；`--color-app-background` 带 alpha，不能单独用于兜底 |
| reduced-motion 下信息丢失 | 中 | 只去掉装饰（位移/旋转/进出场），保留状态（当前行、色块、填充比例）|
| CSS Modules 类名哈希 | 中 | 所有自动化断言只用 `data-*` / `aria-label` / `data-view` |
| 包体积膨胀 | 中 | 明确不引 three.js/Pixi；`dist/renderer.js` 设阈值；模式用 `defineAsyncComponent` |
| 面板遮挡歌词 | 中 | 打开面板时歌词区**收窄**而非被盖住；用 `getBoundingClientRect` 断言 |
| i18n 遗漏 | 低 | 新键必须四语言齐全（`zh-cn/zh-tw/en-us/ko-kr`），否则界面会显示 key |
| 键盘冲突 | 低 | 先列 `common/hotKey` + 主进程 `hotKey` 已占用组合，再定 |
| 主进程被牵动 | 低 | L1–L4 **不需要**改主进程；若将来要做独立窗/OBS 源，走 `winLyric` 的现成范式 |

**统一测试方法（沿用本项目已证明有效的四件套）**

1. **零依赖单测**：`.cjs` + `node:assert/strict`，用 `module.stripTypeScriptTypes` + `data:` URL 载入 `.ts`（`build-config/test-immersive-lyric.cjs` 的现成做法），并入 `npm test`。
2. **CDP 端到端**：`--remote-debugging-port`；`Page.enable` + `Runtime.enable`；**必须** `Page.reload` 后条件轮询（SFC `<style module>` 的 HMR 常不热替换，验到旧 CSS 会假 FAIL）；`Emulation.setFocusEmulationEnabled(true)` 才能让 `document.hidden=false`。
3. **交互注入**：本环境 **CDP 合成鼠标无效、DOM `el.click()` 有效**（Stage 8 实证）；但断言仍要读**状态**不读外观。
4. **视觉与遮挡**：截图必须来自本次运行；判断"是否被遮挡"用 `elementFromPoint` 命中测试，不要只信截图（headless 合成暗层不可靠）。

### 9.2 两个「主动缩小范围」的决定（附理由）

1. **`.line` 容器与行状态类留在 `classic.vue`，`LyricLineView.vue` 只画行内文字。**
   原因：`.line` 与 `.leaveActive { position: absolute }` 是同一条层叠链上的同权重规则，
   拆到两个 CSS Modules 后注入顺序不再可证 —— `.leaveActive` 一旦先注入，退场行就不会脱离文档流，
   整列会「啪」地跳一下。按任务要求「无法证明零回归就缩小拆分」，只把叶子内容（`p/span` 与
   `fillText`/`word_*`/`translation`）搬进 `LyricLineView`。
2. **时钟抽出成 `useImmersiveClock.js`（任务允许「仅当安全时」）。**
   抽法是**逐行搬运**，没有改任何判定：仍是同一个 `audio.currentTime`、同一组
   `playing/pause/ended/emptied/timeupdate` 订阅、同一条 1Hz heartbeat、同样在 `onMounted/onBeforeUnmount`
   里注册与释放。之所以抽出来，是因为舞台与模式都必须拿同一个 `nowMs`，留在组件里会导致 L4 复制粘贴。

### 9.3 注册表设计

```js
{ id, label, labelKey, order, component }   // 最小契约
DEFAULT_MODE_ID = 'classic'
```
- **显式静态列表**，不用 Vite 的 `import.meta.glob`，也不用 `require.context`（后者把「哪些文件算模式」藏进文件名约定）。
- **加载即自检**：id 必须是非空字符串且唯一、`component` 必须存在、默认模式必须已注册 —— 否则模块加载时直接抛错，避免用户切模式时静默白屏。
- `getMode(id)` 对未知 id **回落 classic**（L2 接设置项后，脏数据/缺键也安全）。
- L4 模式变多时把 `component` 换成 `defineAsyncComponent(() => import(...))` 即可分包，契约不变。

### 9.4 侧栏：让位而非遮挡，Esc 不双动作

- 默认关闭 → `v-if` 为假，**不渲染任何节点**，所以关闭态 DOM 与拆分前完全一致。
- 打开时给**三条主带**同时加右内边距（歌词区 `8%`、顶栏 `22px`、底栏 `26px`，各 `+320px`）：
  歌词不被遮，且底部播放控件与右上关闭键也不会被面板压住。
  实测：歌词区 `102.398px → 422.398px`，底栏 `26px → 346px`。
- 背景三层是 `absolute left/right:0`，不参与收窄 → 面板底下仍是同一张封面 + 暗幕，不会出现硬边。
- **一次按键只做一件事**：`Escape` 时若面板开着 → 只关面板；否则 → 退出沉浸视图。

### 10.4 三个实现决策的理由

1. **播放模式自绘，而不是复用 `common-toggle-play-mode-btn`**：该组件是「按钮 + material-popup 弹层」，
   弹层定位在 320px 侧栏内会被 `PanelShell` 的滚动容器裁切。L2 **只复用业务逻辑**
   (`useNextTogglePlay` / `setTogglePlayMode`) 与既有 i18n 键，控件本身自绘。
2. **侧栏移进 `.mainArea`（顶栏+歌词区的新包裹层）**：让面板的定位上下文**只覆盖主区**，
   底部播放栏在 `.mainArea` 之外 —— 于是「让位模式不挤压底栏、覆盖模式也不遮挡底栏」成为结构保证，
   而不是靠给 footer 加内边距去躲。代价是多一层 DOM，已用同实例 A/B 证明**逐像素无影响**（见 10.6）。
3. **键位改走 `key_event`**：`event/keyEvent.ts:26-44` 已经统一处理了三件事 ——
   命中已配置热键只发 action（不发 `key_p_down`）、`event.lx_handled` 已置位直接 return、
   焦点在 INPUT/SELECT/TEXTAREA 时 return。沉浸视图只需处理「轮到自己」的那一份，并在处理后置位 `lx_handled`。
