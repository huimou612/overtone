# 泛音 · 能力地图

> 一句话：**你打开泛音看到的界面，是 LX Music 原样继承的；泛音自己写的东西全部在主进程里，  
> 而且目前只有两个入口，都藏在播放详情页的歌词右键菜单里。**
>
> 建档日期：2026-10-13　｜　对照基线：上游 `lyswhut/lx-music-desktop` v2.12.6（commit `ad95d509`）

## 2. 三层资产清单

### 🟦 继承层 · LX Music 原样（97.6%）

界面、播放器、桌面歌词窗口、音乐库、搜索、排行榜、歌单、我的列表、本地音乐、  
音效、下载管理、数据同步、开放 API、自定义源导入、主题系统 —— **全部继承，未改动逻辑**。

也就是说：**「所有功能基本都是洛雪的」这个判断是准确的**，因为方案 A 从一开始就是这么定的  
（LX 外壳 + Folia 能力层）。区别不在这层。

### 🟪 能力层 · 已移植（Folia，2 项，19 个文件）

| 能力              | 来源                                                                              | 主进程位置                              | 渲染层位置                                    | 状态     |
| --------------- | ------------------------------------------------------------------------------- | ---------------------------------- | ---------------------------------------- | ------ |
| **AI 歌词分词**     | Folia `aiTextClient.cjs` / `aiCredentialStore.cjs` / `lyricSegmentationService` | `src/main/modules/ai/`（8 文件）       | `AiLyricModal.vue`、`SettingAi.vue`       | ✅ 阶段 3 |
| **音源分离**（人声/伴奏） | Folia `electron/analysis/*`                                                     | `src/main/modules/analysis/`（6 文件） | `StemModal.vue`、`core/analysis/stems.ts` | ✅ 阶段 4 |

### 🟩 自研（5 项）

| 能力                    | 主进程位置                               | 渲染层位置                                               | 状态       |
| --------------------- | ----------------------------------- | --------------------------------------------------- | -------- |
| **入场动画**（可定制）         | `src/main/modules/winSplash/`（2 文件） | `SettingAppearance.vue`                             | ✅ 阶段 7.1 |
| **动态壁纸**（视频 + 模糊/遮罩）  | `app.ts` 的 autoplay-policy 开关       | `AppBackground/index.vue`、主题编辑器壁纸分组                 | ✅ 阶段 7.2 |
| **双档外观**（经典 / 个性）     | —                                   | `App.vue`（侧栏浮层）、`View.vue`（过渡）、`usePersonalMode.ts` | ✅ 阶段 7.3 |
| **跟随封面取色**            | `src/main/modules/coverColor/`（读图）  | `useCoverColor.ts`（量化）、`AppBackground/.tint/.mask`  | ✅ 阶段 7.4 |
| **通透主题**（澄澈泛音 / 澄澈夜色） | —                                   | `createThemes.js`（2 套主题）、主题编辑器「一键通透」                | ✅ 阶段 7.5 |

入场动画来源是用户的产品诉求，两边都**没有现成可抄的**：Folia 的 `AppSplashGate.tsx` 只有 408 字节，  
作用是「首帧渲染后把内联遮罩淡出 320ms」，那是遮白不是动画；LX 侧则完全空白。  
取舍与四个坑见 `06-个性化外壳.md`。  
动态壁纸则是 LX 静态背景图的升级（视频 / 模糊 / 遮罩），坑见同文档第 8 节。  
双档外观是同**一套界面的两种形态**（不是两套界面），理由见同文档第 3、9 节。  
跟随封面取色是「读图在主进程、量化在渲染层」的拆分（`<canvas>` 会被 file:// 与跨域图污染，  
`nativeImage.toBitmap()` 的通道顺序有歧义）。  
通透主题是前两者的**收口**：功能做完了但默认主题下看不见，于是补一套内容层带 alpha 的内置主题，  
再把「把内容层调透」从取色器的 alpha 通道里提出来做成一个按钮。见同文档第 11 节。

## 3. 入口位置（这是关键）

| 入口          | 位置                   | 性质                                           |
| ----------- | -------------------- | -------------------------------------------- |
| 「AI 歌词分词」   | 播放详情页 → 右键歌词 → 菜单第一项 | **功能入口**                                     |
| 「音源分离…」     | 播放详情页 → 右键歌词 → 菜单第二项 | **功能入口**                                     |
| 设置 → AI     | 设置页新增的一个分类           | **只是配置**（提供方、密钥、模型、测试连接），不干活                 |
| 设置 → 外观与个性化 | 设置页新增的分类（排「基本设置」之后）  | **只是配置**（外观模式 / 入场动画的开关、图片、标题、时长 / 跟随封面取色开关） |

两个能干活的功能，**必须正在播放一首歌、并打开播放详情页，右键歌词才能真正摸到**。  
首页、侧栏、设置里都看不到它们。

这是「看起来还是一台 LX」的结构性原因：原计划的流程图（`01` 第 4.2 节）里写着  
「`src/renderer/views/` ← 新增 Vue 页面 + 挂路由」，但实际做的时候两个能力都做成了  
**对话框组件**，挂在既有菜单上。省事、破坏性小，代价是**差异化不可见**。

## 4. 红线（2026-10-14 已清理完毕）

`01-缝合方案与执行路线.md` 的红线第 1 条是「不内置任何平台音源接口」。

**注册表：上游清空了。** 提交 `1ff6a006 移除所有内置源` 把  
`src/renderer/utils/musicSdk/api-source-info.ts` 清成了一个空数组：

```ts
const sources: Array<{ id: string, name: string, disabled: boolean, ... }> = [
  // （全部注释掉，一个都没注册）
]
export default sources
```

**实现：2026-10-14 已整体删除。** `kw/ kg/ tx/ wy/ mg/ bd/`（81 文件）+ `xm.js` + `utils.js`，  
合计 **83 个文件**，其中 `kg/vendors/infSign.min.js` 是酷狗的签名算法。

| 目录            | 文件数    | 体积（删除前）       |
| ------------- | ------ | ------------- |
| `musicSdk/wy` | 14     | 54,566 B      |
| `musicSdk/tx` | 14     | 74,759 B      |
| `musicSdk/kg` | 17     | 122,219 B     |
| `musicSdk/kw` | 13     | 60,740 B      |
| `musicSdk/mg` | 16     | 80,575 B      |
| `musicSdk/bd` | 7      | 18,231 B      |
| **合计**        | **81** | **411,090 B** |

⚠️ **一个必须纠正的判断**：清理前我们写的是「这 411 KB 目前是死代码，没有任何调用路径  
能走到」。复核后发现**只对了一半** —— 取音频那条链（`getMusicUrl` / `getLyric` / `getPic`）  
确实死，因为平台 `index.js` 只是 `return apis('xx')...` 而注册表为空；但  
**搜索 / 榜单 / 歌单 / 热词是活的**，`musicSdk.kw.musicSearch` 之类的真实实现会直接请求  
平台服务器。所以清理不是打扫死代码，而是**拆掉一个还在通电的开关**。详见 `01` 的阶段 5。

**代价（已知并接受）**：搜索、榜单、分类歌单、热词、评论、换源候选全部失空 ——  
它们都靠那些平台实现，而自定义源协议只注册 musicUrl / lyric / pic。  
在线能力从此只走用户自行导入的源；本地音乐不受影响。

**删完才发现的第二层**：上游虽然清空了注册表，但**实现还在**，所以它从没测过  
「一个源都没有」的状态 —— 那些页面默认 `musicSdk[source]` 一定是个对象。实现删掉后  
暴露出三类未捕获 rejection（页面不白屏，但控制台刷错、状态看着像坏了）。

实机逐页验收时又发现更多，归纳起来是**四层兜底**：

| 层        | 做什么                                                                                                                        |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| **默认值**  | `DEFAULT_SETTING` 里 4 处硬编码的 `'kw'` / `'kw__16'` / `'new'` → 空串。否则**全新用户第一次打开**就是脏的                                         |
| **数据读取** | `utils/data.ts` 读设置时把失效 source 归一化。**这层不能省** —— `getViewPrevState` 恢复上次视图、深链接都会把 `?source=kw` **显式**塞进 URL，绕过页面守卫          |
| **分发**   | Proxy 空壳返回形状对齐的空结果。⚠️ **形状只能从消费点反推**（第一版猜了四处都不对：`tipSearch` 要裸数组、评论要 `comments`、标签要 `{tags,hotTag}`、还漏了 `songList.search`） |
| **路由**   | 各页守卫里回落（搜索页 → `'all'`，它是聚合视图要进白名单）                                                                                         |

**并且验证要从网络层正面取证**：界面上没有入口 ≠ 不发请求。用 CDP 的  
`Network.requestWillBeSent` 抓到过一个 `img1.kuwo.cn` 的封面请求 —— 来源是**用户自有数据**  
（`OvertoneData/overtone.data.db` 里那首歌记着的封面地址），不是代码内置的接口  
（全仓 grep 平台域名 **0 命中**）。所以断言分两级：**平台「接口」类请求必须为 0**（这才是红线），  
图片类请求逐条打印供人工确认。README 的措辞据此改成精确表述。

详见 `01` 的阶段 5 与 `02-执行手册` 第 21 章。

## 5. 能力显性化（阶段 6，已完成）

`01` 里原本只规划到阶段 5（清红线、补 README、发 Release）。但阶段 5 做完之后，  
泛音对外的样子仍然是一台换了皮肤的 LX —— 因为新增的 2.4% 藏在两层点击之下。

要让它「不再是 LX」，缺的不是新能力，是**把已有能力抬到显性位置**。三个可选做法：

| 做法             | 内容                                                              | 破坏性            | 效果                   |
| -------------- | --------------------------------------------------------------- | -------------- | -------------------- |
| **A. 独立工作台页面** | 仿 Folia 的信息架构，在侧栏加一个「工作台 / AI」一级入口，页面里直接列出：音源分离、AI 歌词、模型管理、历史任务 | 中（新增 1 个 view） | 最强。首次打开就能看到"这软件多了什么" |
| **B. 播放页常驻按钮** | 播放详情页加一行工具按钮（分离 / 分词），不用右键                                      | 小              | 中。至少不用猜右键            |
| **C. 首页卡片**    | 侧栏空白区或首页放一排「AI 能力」卡片，点击跳到对应操作                                   | 小              | 中                    |

**实际采用的是 A + B 组合**：A 解决「陌生用户看不见」，B 解决「已知用户每次多点两下」。  
C 没做 —— 能力卡放进工作台页面之后，首页再摆一排就成了同一件事的第二个说法。

### 落地清单

| 入口          | 位置                                                             | 做什么                                  |
| ----------- | -------------------------------------------------------------- | ------------------------------------ |
| 侧栏一级入口「工作台」 | `views/Workbench/index.vue` + `router.ts` + `Aside/NavBar.vue` | 摆出当前歌曲、两张能力卡（各带前置条件徽章）、分离模型与导出目录     |
| 播放详情页工具行    | `PlayDetail/components/AiToolBar.vue`                          | 三个胶囊：分词 / 分离 / 工作台。前两个直接开对话框，第三个跳工作台 |
| 右键歌词菜单（原有）  | `PlayDetail/components/LyricMenu.vue`                          | 保留不动 —— 就近操作与显性入口是两件事，不是替代关系         |

工作台**刻意不做任务历史**：分离产物是按文件名导出的，本地没有作业表可列。  
为它新造一份持久化状态，等于凭空多出一处会跟真实文件不同步的东西 ——  
所以那一栏只提供「打开导出目录」，让文件系统自己当那份清单。

进页面时重读一次状态（不是缓存）：用户完全可能是「刚在设置里填完 Key / 刚下完模型」  
再切过来的，缓存住旧状态就等于骗人。

细节与验证脚本见 `02-执行手册` 第 19 章。
