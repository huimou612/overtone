# 06 · 个性化外壳

这份文档回答两件事：

1. 用户提的「双模式（经典洛雪界面 / 个性 Folia 界面）+ 可定制入场动画 + 壁纸」这个方案
   **到底贵在哪**，以及为什么它不是一件事而是三件。
2. 阶段 7.1「入场动画」是怎么实现的，以及过程中踩到的坑。

所有数字都来自实际清点（`git diff`、源码统计、真机实测），没有估算值。

---

## 1. 用户提案的拆解

原话要点：

> 「点开有我们泛音的入场动画，这个动画可以定制；可以弄一个入口，里面可以放壁纸。
> 既然是洛雪和 Folia 缝出来的，就做一个模式选择 —— 经典模式套洛雪界面，个性模式用 Folia 的界面。
> 音频功能（音源分离）也可以加上去。」

拆开后是三件独立的事，成本差一个数量级：

| 块 | 现状（已核查） | 成本 |
|---|---|---|
| 入场动画 | LX **完全没有**。`src/main/modules/winMain/main.ts` 只创建主窗口（`show: false` 等 `ready-to-show`），无 splash 窗口、无首屏遮罩 | 低，纯新增 |
| 动态壁纸 | LX **已有静态版**：主题编辑器的「背景图片」(`theme_edit_modal__bg_image`)，18 个内置主题 + 10 个自定义主题槽 + 23 个可调项 | 低，是升级不是重造 |
| 双模式界面 | 无。且外壳是 Vue、Folia 界面是 React | 取决于做法，最高到「极高」 |

两处容易误判的细节：

- **Folia 的 `AppSplashGate.tsx` 不是入场动画**。它只有 408 字节，作用是「首帧渲染完成后把
  `index.html` 里内联的遮罩淡出 320ms」（`utils/appSplash.ts`）。这是**遮白**，不是动画。
  真正管启动流程的 `hooks/useStartupExperienceGate` 管的是发布说明/引导，也与动画无关。
  所以「入场动画」在两边都没有现成可抄的。
- **Folia 的 `components/wall/` 不是壁纸**。从文件名看（`WallToolsQueueIsland`、`useWallPointerPan`、
  `flipPlan`、`seamPlan`、`blockReflows`、`rankSlots`）它是一套**无限画布式的内容墙**
  （拖拽 / 平移 / 翻牌），是 Folia 的主界面，跟桌面壁纸无关。

## 2. 「用 Folia 的界面」到底有多重

Folia 源码在 `fusion-music/reference/folia-major`（不在本仓库内），以下是清点结果：

| 项 | 数量 |
|---|---|
| React 组件 | **457 个 tsx**（`components/` 354、`library/` 80、`mods/` 19） |
| 状态层 | **40 个 zustand store** |
| 可视化器 `components/visualizer/` | **407 文件 / 6.97 MB**（@react-three/fiber + drei + postprocessing + @paper-design/shaders） |
| 招牌格子歌词 `components/app/lattice/` | 32 文件 / 148 KB（canvas 渲染） |
| 主界面 `components/wall/` | 35 文件 |
| 动画 / 样式 | framer-motion + animejs；Tailwind v4 |

而泛音的外壳是 **Vue 3**。「组件不能互搬」这条在阶段 0 就写进方案了，但当时没料到会想直接换壳。

### 真正的成本不在画界面，在状态

播放状态活在 Vue 的模块级响应式里（`window.lxData.playMusicInfo` 那一套），React 侧完全看不见。
要让两个壳共享「同一首正在播的歌」，只有两条路：把播放 / 队列 / 歌单**下沉到主进程**（等于重写
LX 的数据层），或者做一层**数据中继**（两个渲染进程都跟主进程要数据，但要自己处理一致性与真相源）。
两条都不便宜。

### 我去数了 lattice 的依赖，结论和预期相反

原本以为 Folia 的招牌视觉（动态歌词）是自包含的 —— 输入音频+时间轴+歌词、输出 canvas，边界很干净。
实际把 `components/app/lattice/` 的外部 import 全数出来之后：

| 类别 | 实际情况 |
|---|---|
| 必带的核心 | `visualizer/monet/monetLyricsModel`、`monetLyricMotion`（8 处引用） |
| 必须带的状态 | `useLatticeSettingsStore`、`useLatticeControlsStore`、`useWallHandoffStore` |
| 宿主耦合（可裁） | `components/wall/layout`（7 处）、`WallBackButton`、`WallToolsButton`、`WallToolsRows`、`ProgressBar`、`floating-player/playerControlSlotActions` |
| 意外触点 | `services/onlineMusic/songMetadata` |
| 包依赖 | react、framer-motion、**pixi.js**、react-i18next、lucide-react |

而且 `LatticeLyrics.tsx` 只有 1826 字节 —— 它的数据**不从 props 来**，是从 `useLatticeLyrics()`
这个 Provider context 拿的。所以切片不是「搬过来就能用」，而是「搬过来 + 裁掉宿主耦合 + 改成 props 驱动」。

## 3. 四种做法与推荐

| 做法 | 实质 | 成本 | 拿到什么 |
|---|---|---|---|
| 真双壳 | 两个渲染入口，Vue 一套 React 一套 | **极高**：播放状态层要重写到主进程 | Folia 的完整界面（含无限画布内容墙） |
| **切片复用**（推荐） | React 只装一个视觉模块，用 webview 嵌进 Vue | 中高：要做依赖闭包提取与裁剪 | Folia 最值钱的歌词视觉 |
| Vue 重写 | 只借设计语言，界面全部自己写 | 中 | 神似，但拿不到 Three.js/着色器那套 |
| 单壳双皮肤 | 外壳不变，做两档皮肤与动效强度 | 低 | 观感上的「个性」 |

### 为什么推荐「切片复用」

**做法 1 用大约 20% 的成本拿到 80% 的「这就是 Folia」观感** —— 人对「这是哪个软件」的判断，
八成来自播放页那一眼（动态歌词 + 3D 背景），不来自侧栏有几个菜单。

但要说清两点：

1. **做法 1 是做法 3 的第一段，却不会自动通向做法 3**。做法 3 的成本大头是状态中继，
   它不会因为先做了做法 1 而减少一分。所以别把它当「分两步就能到达」，那是虚假的乐观。
2. **做法 3 真正的风险不是技术，是功能不对称**。Folia 的定位是「一个动态歌词播放器」，
   它的信息架构里没有歌单管理 / 本地音乐 / 下载 / 批量编辑 / 设置体系这一整套。
   真双壳最后会撞上：个性模式里放不放这些？放进等于重写一遍功能 UI；不放进，
   用户切过去发现少一半功能，**反而比只有一套界面更差**。

### 所以个性模式做「沉浸形态」，不做「第二套界面」

> **经典模式** = LX 原样（管理为主，信息密度高）
> **个性模式** = 同一套界面的**沉浸形态**：侧栏收起、播放页全屏、歌词换成 Folia 的 lattice 视觉、
> 入场动画与动态壁纸生效

功能一个不少，只是「管理态」和「沉浸态」的差别 —— 这才是真实用户会来回切的两种状态。
技术上它正好是**阶段 7（Vue 侧）+ 阶段 8（切片）**的组合，且不需要状态中继。

## 4. ⚠️ 红线被加重了（这一节比成本问题重要）

清点依赖时发现：**Folia 自己内置了四家平台的音源实现**。

- `electron/neteaseBackend.cjs`、`neteaseApiStartup.cjs`
- `electron/qqBackend.cjs`、`qqApiStartup.cjs`
- `electron/bodianApiBridge.cjs`、`electron/kugouApiBridge.cjs`
- `src/services/onlineMusic/{qq,bodian}Provider|Transport`
- 依赖里有 `@neteasecloudmusicapienhanced/api`、`@yakult-green-tea/qq-music-api`、`bodian-music-api`、`kugoumusicapi`

而 LX 上游是**主动移除**内置源的（`1ff6a006 移除所有内置源`）。两边方向正好相反。

**结论：复用 Folia 代码时边界必须卡死。**

| 可以要 | 一个都不能带 |
|---|---|
| `components/visualizer/`（3D 可视化器） | `src/services/onlineMusic/` |
| `components/app/lattice/`（格子歌词） | `electron/*Backend.cjs`、`*ApiBridge.cjs`、`*ApiStartup.cjs` |
| `utils/lyrics/`（歌词解析与渲染提示） | 任何 `*music-api` / `*musicapi` 依赖 |

否则红线会从「树里躺着 411 KB 死代码」升级成**「我们主动引入可运行的音源实现」** ——
性质完全变了，那是我们自己的责任，不再有「上游就是这么带的」这个说法。

## 5. 7.1 入场动画的实现

### 5.1 为什么需要它

启动链路上有一段真实的空窗期：

```
app.whenReady()
  └─ init()                                     ← 可以在这里插东西
       ├─ initAppSetting()   异步，要等数据库初始化（worker dbService.init）
       └─ registerModules()  ← 到这一步才 createWindow()，而窗口是 show: false
            └─ ready-to-show ← 渲染进程就绪后才显示
```

也就是说从「点图标」到「看见界面」之间，要依次等：数据库初始化 → 主窗口创建 → 渲染进程加载。
生产环境是几百毫秒到一两秒，开发环境更久（还要等 webpack dev server 编译）。

### 5.2 为什么是独立窗口，而不是渲染层遮罩

渲染层遮罩（Folia 的做法）不需要额外进程，但它**填不上空窗期的前半段** —— 遮罩本身要等 bundle
加载完才能渲染，而那段空窗正是「bundle 还没加载完」。用独立窗口才能真正盖住整段。

### 5.3 时序：先创建，后刷配置

```
app ready
  ├─ createSplashWindow()      用默认外观立刻显示（此时 global.lx.appSetting 还是 defaultSetting）
  ├─ await initAppSetting()    设置读完
  ├─ applySplashSetting()      把真实外观注入页面；若用户关了开关则立即淡出
  └─ registerModules()         主窗口创建
       └─ ready-to-show
            └─ requestClose()  不足最短时长则等满 → 淡出
```

两个刻意的设计：

- **不等设置读完再显示**。设置读出来之前那几百毫秒正是要填的空窗，等设置的话就白做了。
  代价是首帧只能用默认值，所以 `configQuery()` 会先塞一版（哪怕只是默认值）——
  否则页面会先用白底渲染再变黑，闪一下。
- **外观用 URL query 传入，不走 IPC**。splash 页面不需要 preload、不需要 Node 能力，
  纯静态 HTML + 内联 CSS/JS 就能跑完，攻击面最小。真实配置随后用 `executeJavaScript`
  调用页面的 `window.__overtoneSplashApply(...)` 刷入。

### 5.4 三重保底

| 机制 | 参数 | 防的是什么 |
|---|---|---|
| 最短显示时长 | `common.splashMinMs`（默认 1400ms） | 启动快的机器上一闪而过，观感比没有更差 |
| 兜底上限 | 生产 15s / 开发 60s | 主窗口迟迟不就绪时，alwaysOnTop 的窗口挡住界面让人以为卡死 |
| 开关 | `common.splashEnable` | 用户不想看就关掉 |

开发模式的兜底上限必须放宽：主窗口要等 webpack dev server 编译（本项目约 40~60s），
沿用生产的 15s 会让入场动画提前收掉，看到的是「闪一下然后一片空白」。

### 5.5 可定制项

| 配置键 | 默认 | 说明 |
|---|---|---|
| `common.splashEnable` | `true` | 开关 |
| `common.splashMinMs` | `1400` | 最短显示时长（0.8 / 1.4 / 2 / 3 秒四档） |
| `common.splashImage` | `''` | 自定义启动图，空则用内置声波标识 |
| `common.splashTitle` | `''` | 标题文字，空则显示「泛音」 |

入口在设置页新增的「外观与个性化」分组（`SettingAppearance.vue`），为 7.2 壁纸与 7.3 双档留了位置。

## 6. 踩到的坑

### 6.1 CSS 动画反向写会得到一个纯黑卡片

第一版是 Electron 的常见写法：

```css
.title { opacity: 0; animation: rise 520ms forwards; }
```

这个写法**在所有元素上都依赖动画把内容显示出来**。截图时我看到的是一个纯黑卡片 ——
因为窗口隐藏时不参与合成，动画一帧都没走，元素全部停在 `opacity: 0`。

这不只是截图问题：真实环境里系统禁用动画、或者渲染被节流时，入场动画会退化成一个**黑方块** ——
比没有更难看。改法是把基础状态改成「可见」，动画只负责从 `from` 淡入：

```css
.title { animation: rise 520ms 160ms backwards; }
@keyframes rise { from { opacity: 0; transform: translateY(6px); } }
```

`backwards` 让延迟期间停在 `from`，动画结束后回到元素基础值（可见）。
**动画不推进时最差也是「静态好看」。**

### 6.2 隐藏窗口的 CSS 动画不推进

同一件事的另一面：`win.capturePage()` 在 `show: false` 的窗口上拿不到动画后的画面，
即使 `paintWhenInitiallyHidden` 默认为 true。截图脚本必须先 `showInactive()`。

### 6.3 `destroy()` 掉唯一窗口会触发应用退出

拍第二张图时报 `ERR_FAILED (-2) loading ...`。原因是第一张拍完 `win.destroy()`，
唯一的窗口没了 → 触发 `window-all-closed` → 默认行为是 `app.quit()` → 应用开始退出，
第二个 `loadFile` 自然失败。改成一个窗口来回换参数，并显式接管 `window-all-closed`。

### 6.4 `__dirname` 在 dev 下是可用的（确认过，不是坑）

`splash.html` 是按 `path.join(__dirname, 'splash.html')` 找的，而这是本项目第一个在 dev 下
依赖 `__dirname` 的功能（`winMain` 的 dev 分支走 `http://localhost:9080`，从来没用过它）。

确认结论：`build-config/main/webpack.config.base.js` 里 `target: 'electron-main'`，
webpack 对该 target 下 `node.__dirname` 的默认值就是保留真实值；prod 配置里那两行
`node: { __dirname: false, __filename: false }` 是显式声明同一件事。
`sidecar.cjs` 用同样方式找 `stems_runner.py` 并在 dev 验证通过，是旁证。

前提是别忘了往两个 webpack 配置的 `CopyWebpackPlugin` 里都加拷贝 —— 只加 prod 的话，
dev 里会永远报「找不到 splash.html」，和当初 `stems_runner.py` 是同一个坑。

## 7. 验证方式

| 脚本 | 验的是什么 | 怎么验 |
|---|---|---|
| `build-config/probe-splash.py` | **时机**（这是核心） | 0.3s 轮询 CDP `/json`，记录每个页面目标的出现/消失，判定「splash 先出现、主窗口就绪后消失」 |
| `build-config/probe-splash-shot.js` | **外观** | 直接按 query 参数渲染 splash 并 `capturePage()`，出暗色/亮色两张留档图 |
| `build-config/drive-appearance.js` | **设置项真的渲染出来了** | 导航到 `#/setting`、点开分组、读回 DOM 文本与 placeholder |

第三个脚本存在的理由：lint 和 webpack 都过了，但 `base-selection` 的 list 形状、`base-input`
的 placeholder 这类东西错了不会编译报错，只会渲染成空白。

实测结果：

```
观测时长 3.8s
     0.00s  出现  SPLASH  file:///.../dist/splash.html?title=泛...
     0.93s  出现  MAIN    http://localhost:9080/?os=windows&...
     3.81s  消失  SPLASH  (存活 3.81s)
PASS：splash 出现、并在主窗口就绪后消失
```

设置页读回：侧栏出现「外观与个性化」，面板文案、标题输入框的 placeholder（「留空则显示应用名」）、
「选择图片」按钮全部正确。
