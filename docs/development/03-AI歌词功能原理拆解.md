# AI 歌词功能 —— 原理拆解

> 对象：Folia 的「歌词分词（Lyric Word Segmentation）」功能
> 源文件：`shared/lyricSegmentationPrompt.cjs`（14.5 KB）、`shared/lyricSegmentationService.mjs`（12.8 KB）、`electron/aiTextClient.cjs`（33.7 KB）、`electron/aiCredentialStore.cjs`（7.4 KB）
> 这份文档解释「它怎么工作」和「为什么这么设计」。移植时照此实现即可。

---

## 1. 这个功能到底做什么

**一句话：把一行歌词切成「词」，并且保证切完拼起来和原文一字不差。**

```
输入：  把回忆拼好给你
输出：  ["把", "回忆", "拼好", "给", "你"]
```

**为什么要这么切？** 因为 Folia 的歌词动画是**逐词高亮**的——要做出「字一个一个跳出来」的效果，必须知道每个词的边界在哪。而中文没有空格，机器不知道「回忆」是一个词还是两个字。

**这就是整个功能的立身之本**：不是「翻译歌词」「润色歌词」，而是**分词**。选择这个任务很聪明——它：
- 是机械任务（不需要创造力）→ 可以用便宜、快速的模型
- 有客观正确性（能无损还原）→ 能自动校验
- 一次做完永久缓存 → 成本极低

        │

## 3. 四层资产与各自职责

| 层 | 文件 | 职责 |
|---|---|---|
| **提示词层** | `lyricSegmentationPrompt.cjs` | 规则文本、两个 provider 的 schema、解析与还原校验 |
| **编排层（服务端）** | `lyricSegmentationService.mjs` | 选择 provider、走推理抑制阶梯、发请求、错误映射 |
| **客户端层（桌面端）** | `electron/aiTextClient.cjs` | 与上面同构，但跑在 Electron 主进程，用 electron-store 拿配置 |
| **凭据层** | `electron/aiCredentialStore.cjs` | API Key 加密落盘、渲染层永远拿不到明文 |

> 📌 **注意这个双份设计**：`.cjs` 给 Electron 主进程，`.mjs` 给 Vercel Edge / Cloudflare Worker。作者在注释里明说了原因——「theme 功能最后变成了四份拷贝，不想再来一次」。**这是值得学的工程习惯：同一套逻辑，两种运行时，抽成共享模块而不是复制粘贴。**

## 4. 工程决策清单（每条都有实测数据）

这些注释是**这个项目最值钱的部分**——真金白银的实测经验：

| 决策 | 实测依据 |
|---|---|
| Gemini 关掉思考（`thinkingBudget: 0`） | 开思考 9.0s，关掉 1.6s，**输出字节完全相同**。分词是机械任务，没有可推理的东西 |
| `reasoning_effort: 'none'` | deepseek-v4-flash 不加这个：把整个 token 预算烧在推理上，52 秒后返回**空答案**；加上：约 1 秒出结果 |
| `'minimal'` 不管用 | 实测 `reasoning_effort: 'minimal'` 仍会烧完全部预算。必须是 `'none'` |
| 必须有 Gemini schema | 不约束输出形状时模型会自我重复：同一个 12 行请求三次测得 **7KB / 14KB / 37KB**，延迟 **8s / 16s / 42s**，长度和延迟同步增长 |
| 输出上限 8192 tokens | 实测约 18 tokens/行（150 行 → 2707 tokens），100 行一批远在预算内 |
| **日语规则 + 2 个日语示例是「承重」的** | 只有中英示例时，弱模型把英文行理解成「按空格切」然后套用到所有语言。deepseek-v4-flash 在 19 行日语上，5–10 行原样返回不切（1.6–2.4 段/行，而 `Intl.Segmenter` 给 7） |
| 抽象规则没用，示例才有用 | 光加一条「绝不返回整个从句」的抽象规则：**没有改善**（仍有 9 行未切）。加上日语规则 + 两个日语示例行：降到 1 行未切、3.8 段/行 |
| **这个改动不是日语专属** | 加上后中文**不再过度分割**（「摘不下」「盒子里」作为整体保留），英文输出**字节级相同**。Gemini 同样受益：2.8 → 3.4 段/行 |
| 规则 7 的括号条款 | 不加的话新增规则会把 `(拼图女孩)` 拆成三段 |
| 400 行上限 | 请求体守卫，在任何凭据或网络操作**之前**校验 |

**给移植的启示：** 提示词工程在这里不是「写一段话让模型干活」，而是**用实测数据驱动的迭代优化**。你要改规则时，也必须做同样的对照测量。

## 5. 核心精解：`realignSegmentsToText`

**这是整个功能最精彩的一处设计。**

### 问题

模型有个稳定行为：**分割点给得很准，但会顺手把空白字符规范化**——
- 丢掉行尾空格
- 把全角空格折成半角
- 把连续两个空格压成一个

如果直接拿「拼接结果 === 原文」做校验，那么**一个装饰性差异就会让整首歌被丢弃**。

### 解法

> **不信任模型返回的文本，只信任它的边界。**

做法：拿着**原文**走一遍，按模型给的分段去消费原文里的非空白字符，让原文自己的空白落回它实际所在的位置。

结果：每个分段都是原文的一个切片，**它们的拼接必然等于原文——由构造保证，而不是靠模型表现良好。**

只有在**非空白内容真的不一致**时才返回 `null`（模型改写、翻译、漏词），这才是真正该失败的场景。

### 为什么值得学

| 思路 | 说明 |
|---|---|
| 区分「实质」与「装饰」 | 分割点是实质，空白是装饰。只校验实质 |
| 把正确性变成构造性质 | 与其事后校验（可能误杀），不如构造时就保证 |
| 保留真正的失败检测 | 不因为容忍装饰就放过改写 |

这个思路可以直接搬到别的 LLM 结构化输出场景。

## 6. 凭据安全（`aiCredentialStore.cjs`）

**用户要填自己的 API Key，所以密钥管理是绕不开的。Folia 的做法值得照抄：**

| 措施 | 实现 |
|---|---|
| 落盘加密 | Electron `safeStorage`（Windows 走 **DPAPI**、macOS 走 Keychain、Linux 走 libsecret/kwallet），磁盘上只有密文，字段名加 `_SEALED` 后缀 |
| **渲染层永远拿不到明文** | 前端只知道「这个 key 存了没有」（`AI_API_KEYS_CONFIGURED`），表单提交新 key 时传明文，清空时传空串 |
| 防越权写入 | `isReservedAiCredentialKey` —— 密文和状态字段名不允许渲染层写入 |
| 惰性解密 | Linux 上 `safeStorage` 必须等 `app.whenReady()` 之后才可用 |
| 明文迁移 | `migrate()` —— 把旧版本留下的明文 key 重新加密 |
| 防密钥外泄 | `resolveTestApiKey` —— 只有在 URL 与已保存的一致时，才把保存的 key 用于「测试连接」。避免用户改了 URL 后，key 被发到从未授权的主机 |
| 解密失败降级 | 密文来自别的机器/用户，或钥匙串暂时锁着 → 不缓存、不删密文，等钥匙串解锁后自动恢复 |

**这套设计对缝合项目的价值：** 你要做 AI 功能就必须处理 API Key，直接照抄这一套，能省掉一整个安全评审。

## 7. 一个贴心的兜底：手动模式

`buildSegmentationManualPrompt(lines)` 生成的提示词**可以直接复制到任意模型网页**，让模型用 `/` 分隔符返回纯文本：

```
（8 条规则全文）
If you cannot produce JSON, answer with N plain lines instead,
separating words with "/" and nothing else.

Segment these N lyric lines.

1. 把回忆拼好给你
2. ...
```

**这意味着：用户没有 API Key 也能用这个功能。**

对缝合项目来说这是个很好的设计——降低了使用门槛，也让功能在「用户不想配 key」时仍然可用。移植时**务必保留这条路径**。

## 8. 移植到 LX Music 的适配点

| Folia | LX Music | 说明 |
|---|---|---|
| `electron-store` 实例 | `@main/utils/store` 的 `getStore(STORE_NAMES.XXX)` | LX 已有 electron-store 封装，直接注进 `createAiCredentialStore` |
| `safeStorage` | 从 `electron` 引入 | 无变化 |
| Folia 的 IPC 名 | `@common/ipcNames` 新增 `ai` 模块 | 见 `02-执行手册` 第 3 节 |
| Folia 的 React 设置界面 | **用 Vue 重写** | 参照 `src/renderer/views/Setting/` 的目录组织 |
| 分词结果 → 歌词渲染 | LX 的歌词在 `renderer-lyric`（独立窗口） | 分词结果可通过 `winMain_set_lyric_info` 传给歌词窗口 |

**新增依赖（很少）：**
- 无需额外 npm 包 —— 全部用 `fetch`（Node 22 自带）+ Electron 内置的 `safeStorage`
- 这是选它做第一个功能的关键原因：**零额外依赖，零模型文件，零 GPU 要求**

    get_manual_prompt: 'get_manual_prompt',// 拿手动复制用的提示词
    apply_segmentation: 'apply_segmentation', // 写回歌词
  },
```

### 9.2 `src/main/modules/ai/index.ts` 骨架

```ts
import { AI_EVENT_NAME } from '@common/ipcNames'
import { mainHandle, mainSend } from '@common/mainIpc'
import { safeStorage } from 'electron'
import getStore from '@main/utils/store'
import { STORE_NAMES } from '@common/constants'
import { createAiCredentialStore } from './credentialStore.cjs'
import { segmentLyricLines } from './segmentation.cjs'

export default () => {
  const credentials = createAiCredentialStore({
    store: getStore(STORE_NAMES.AI),   // 需要在 constants 里加这个枚举
    safeStorage,
  })

  mainHandle(AI_EVENT_NAME.get_status, async() => ({
    configured: credentials.toPublicSettings({}),
    encrypted: credentials.isEncrypted(),
  }))

  mainHandle(AI_EVENT_NAME.set_credential, async({ params }) => {
    credentials.set(params.key, params.value)
  })

  mainHandle(AI_EVENT_NAME.segment_lyric, async({ event, params }) => {
    const lines = params.lines
    return segmentLyricLines(lines, credentials.settingsView, (progress) => {
      mainSend(event.sender, AI_EVENT_NAME.segment_progress, progress)
    })
  })

  mainHandle(AI_EVENT_NAME.get_manual_prompt, async({ params }) => {
    return buildSegmentationManualPrompt(params.lines)
  })
}
```
