## 1. 问题：红线之后，没有歌可放

阶段 5 为了守住「不内置任何商业平台音源接口」，把上游七个平台实现（kw / kg / tx / wy / mg / bd / xm）
连同酷狗那套签名算法一起删了。删除是对的 —— 那些代码即使不被调用也会被整包打进产物，
等于把平台接口「内置」进了应用。

但删完就露出一个更难看的洞：**这台音乐播放器，没有任何一首歌可以放。**

- 在线搜索：没有源，搜不出东西
- 在线播放：主路径 `musicSdk[source].getMusicUrl(...)` 落到空壳，必然失败
- 剩下的出路只有「让用户自己导入第三方音源脚本」

把风险与门槛丢给用户，不算解决。用户要的是**打开就能听**。

---

## 2. 选型：为什么是 Openverse

清点是能不能用「开放版权曲库」补上这个洞，候选两个：

| 候选 | 单次搜索是否直接给出可播地址 | 授权信息 | 结论 |
|---|---|---|---|
| **Openverse**（WordPress 基金会） | ✅ 直接给 `url` + `filetype` | 有 `license` / `license_url` / `attribution` | **采用** |
| Internet Archive | ❌ 只给「条目」，取可播文件要 N+1 次请求 | 混杂，需自行判断 | 放弃 |

Openverse 聚合的是**明确标注 CC / 公有领域**的音频（Jamendo、Freesound、ccMixter、Wikimedia…），
公开 API、**无需密钥**。挂上它并不违反红线：**内置的是开放版权曲库，不是任何商业音乐平台的接口。**

### 必筛参数

```
category=music
license_type=commercial,modification
```

不加 `license_type` 会混进 `by-nc-nd`（禁商用、禁改编）这类「看着开放、其实不能用」的授权 ——
那就不配叫开放曲库了。代价是结果集小一些（实测 `q=piano` 仍有 240 条）。

## 3. 接口契约（全部实测，不是照文档抄的）

```
GET https://api.openverse.org/v1/audio/?q=&page=&page_size=&category=music&license_type=commercial,modification
GET https://api.openverse.org/v1/audio/<uuid>/     ← 详情
```

| 项 | 实测结果 |
|---|---|
| 响应体 | `{ result_count, page_count, page_size, page, results[] }` |
| **匿名 `page_size` 上限** | **20**。传 30 / 50 直接 **401** |
| `duration` 单位 | **毫秒**（72000 → 01:12） |
| `filesize` | **常为 `null`**（jamendo 整页都是 null；freesound 等才给字节数） |
| `audio_set` | **没有 `id` 字段**，只有 `title / creator / foreign_landing_url / url / filesize / filetype` |
| `filetype` | 实测 `mp32`（也在 `alt_files` 里出现别的容器） |
| `thumbnail` | `https://api.openverse.org/v1/audio/<id>/thumb/` —— **仍在 api 域名下，不是独立 CDN** |
| `attribution` | ✅ 现成的整套署名文案（作品名 + 作者 + 许可证名 + 许可证地址） |
| 详情端点 | 存在 id → 200；不存在 → 404；**`indexed_on` 为 null 的条目 → 500** |
| 中文关键词 | **基本搜不到**（`q=钢琴&category=music` → `result_count: 0`） |

## 4. 实现里的两个取舍

### 4.1 只展示 Chromium 能直接解码的容器

`PLAYABLE_FILETYPES` 只放 `mp3/mp32/ogg/oga/opus/wav/flac/m4a/aac/webm/mp4`。
其余条目不进列表 —— 免得用户点了放不出来。主 `url` 不可播时按
「主 url → 可播的 `alt_files` → 原 url」的顺序找。

### 4.2 不给歌词，但**不 reject**

`core/music/utils.ts:457` 那条消费点要求 `lyric` 里**必须含时间戳**（`existTimeExp`），
落空就会触发 `onToggleSource()` 去换源 —— 白跑一轮还给用户一个报错。

所以 `getLyric` 返回两行带 `[00:00.00]` 的说明，把**曲库自带的 `attribution`** 放在里面。
顺带解决了一个正事：CC-BY 系列本来就要求署名，而歌词面板是这个源唯一稳定的文字展示位。
（缓存未命中时回落成 `openverse.org/audio/<id>` 作品页链接。）

## 5. 接线点：新增一个源要动四处

内置源不是「把模块放进目录」就能用的，缺任何一处都会以难查的方式坏掉：

| # | 位置 | 做什么 | 漏了会怎样 |
|---|---|---|---|
| 1 | `musicSdk/index.js` 的 `sources.sources` | 登记 `{ name, id }` | 搜索页 / 歌单 / 榜单 / 热词那几处 `for (const source of sources.sources)` 遍历不到，**界面根本不出现这个 Tab** |
| 2 | `musicSdk/index.js` 的 `builtinSources` → `Object.assign(sources, ...)` | `{ ...noSource, ...ov }` | `{...sources}` 展开进 `musicSdk` 时拿不到实现，Proxy 落到 `getUserApiSource` → 空壳。**必须与空壳合并**：`musicSdk[source]?.songList.getTags()` 这种写法会让 `.songList` 变 undefined 再炸一次 |
| 3 | `src/lang/{zh-cn,zh-tw,en-us,ko-kr}.json` | `source_ov` / `source_alias_ov` | Tab 显示成原始 id |
| 4 | `src/common/types/common.d.ts` + `music.d.ts` | `OnlineSource` 加 `'ov'` | 类型层看不见它 |

### 5.1 最容易漏的第 5 处：`assertApiSupport`

```ts
// src/renderer/store/utils.ts
export const assertApiSupport = (source: LX.Source): boolean =>
  source == 'local' || isValidSource(source) || qualityList.value[source] != null
```

`qualityList` 是按**所选「音源」**填的（`core/apiSource.ts`），而**内置源不依赖所选音源** ——
它随应用分发，不需要用户导入。只查 `qualityList` 的话，用户一旦选了别的音源，
开放曲库就会「搜得到、播不了」（界面点击时 `assertApiSupport` 为假，直接 `return`，**不播也不报错**）。

⚠️ 也别把它简化成 `musicSdk[source] != null` —— Proxy 会给**任何取不到的 key** 返回空壳对象，
那样每个源都「支持」了。`isValidSource` 是**具名导出**，不在默认导出的 Proxy 上，必须具名 import。

## 6. 网络依赖：这个源连不连得上，只由「设置 → 网络」决定

这是本项目里最容易误判的一条，务必看清：

```ts
// src/main/modules/winMain/main.ts
const setSesProxy = (ses, host?, port?) => {
  if (host) ses.setProxy({ mode: 'fixed_servers', proxyRules: `http://${host}:${port}` })
  else      ses.setProxy({ mode: 'direct' })   // ← 没配代理时「强制直连」
}
```

- 所以 `ov/index.js` **必须用 `fetch`**（走 Chromium 网络栈 = 走主窗口会话代理），
  改动「设置 → 网络」后主进程 `updated_config` 会立刻 `setSesProxy()`，**立即生效**。
- 而 needle（`utils/request.js`）的代理来自渲染层 `proxy` store，那个 store 只在启动时
  从 appSetting 抄一次快照 —— 运行期改设置要重启才跟上。
- ⚠️ **`mode: 'direct'` 会主动关掉系统代理**。所以「代理开着但应用里没配」的情况下，
  这个源也是不通的。唯一的开关就是应用里那一处。
- 实测：`api.openverse.org` **直连 20s 超时**；沙箱出口代理（`127.0.0.1:54942`）也返回 `000`。
  不开代理时搜索直接显示「加载失败」—— **这是网络环境问题，不是代码坏了**。
- 条目的 `thumbnail` 也在 `api.openverse.org` 上，所以**封面同样需要代理**。

## 7. 验证方法与实测结果

脚本：`.git/verify-ov.js`，两种模式：

```bash
node .git/verify-ov.js piano             # 真网络
node .git/verify-ov.js piano --fixture   # 离线（把真实响应塞进 fetch）
```

为什么要两种：本机**没有任何一条路**能到 `api.openverse.org`，真网络模式下四段只会拿到
`Failed to fetch`。而我们其实要证两件**互不相干**的事：

1. **代码链路对不对**（模块 → store → 界面 → 播放主路径）
2. **这台机器能不能连上那个域名**

`--fixture` 用 `.git/ov-fixture.json`（**真实抓到的那份响应**）把 ① 证死，② 用真网络模式如实记录。
两者不能互相替代。

### 判据与结果（`--fixture` 模式，2026-10-15）

| 段落 | 判据 | 结果 |
|---|---|---|
| A 模块直搜 | 导出齐全 + 返回条数/分页 | ✓ 3 条 / `total=240` / `limit=20`（夹紧生效）/ `allPage=12` |
| A2 字段映射 | 对答案，不是「有结果就行」 | ✓ `interval=02:09`（129000ms 毫秒换算正确）、`albumName`/封面有值、`size=null` |
| D 音频地址 | 解析出的 URL 真的能加载 | ✓ **3/3 条 jamendo 音频读到元数据**（129.51s / 122.25s / 204.98s，`readyState=1`） |
| B 界面 | Tab 存在 + 列表渲染出曲名 | ✓ 「开放曲库」Tab；3 行结果（`01-search-ov.png`） |
| C1 | `assertApiSupport('ov')` | ✓ |
| C2 主路径 | 穿过 `handleGetOnlineMusicUrl` | ✓ `quality=128k` → `…jamendo.com/?trackid=150810&format=mp32` |
| C3 封面 | 穿过 `handleGetOnlinePicUrl` | ✓ |
| C4 歌词 | 穿过 `handleGetOnlineLyricInfo` + 时间戳 | ✓ 含真实 CC 署名 |
| C5 | `playListById` 切到目标歌 | ✓ `Le piano troix`（`ov_5d029c9d-…`） |

### 本机**验不到**的部分（必须如实说明）

- **「出声」验不了**：这台机器的 Chromium 建不出音频输出流
  （`PipelineStatus::AUDIO_RENDERER_ERROR`，渲染层 `enumerateDevices()` 连 `audioinput` 都没有，
  进程中也没有音频服务进程）。表现为元数据读得到、`currentTime` 恒为 0。
- 直接后果：播放器「播不出」会**自动跳下一首**，再失败再跳 —— 实测 6 秒内连换 4 首
  （`我不难过` → `小半` → `Bubblegum Dreams` → `Calm Waves`），控制台不断刷
  `core/music/local.ts` 的 `source not found`（本地歌找不到对应在线源，属**正常兜底失败**）。
  **所以 `playListById` 之后必须同步立刻读状态**，晚 1.5 秒就已经跳到别的歌了。

## 8. 踩过的坑（CDP 驱动验证时）

| 坑 | 症状 | 原因 |
|---|---|---|
| **不出一帧，虚拟列表渲染 0 行** | store 里明明有 3 条，界面只有表头 | 窗口 `document.hidden === true` 时 Chromium 不跑 `requestAnimationFrame`，而列表靠 rAF 算可视区间 → 总高算得出（3 行 = 111px）但子元素 0 个。**`Page.captureScreenshot` 会强制出一帧**，所以截图必须排在读 DOM **之前** |
| 把环境当 bug | 看起来像「查询没生效」 | 上面那条，很容易误判 |
| 音频弹窗挡图 | 「音频输出设备为空」常驻内容区正中 | CDP 环境没声卡，可能反复弹，要**循环点掉** |
| 验错对象 | 验「网络通不通」但结论当成「代码对不对」 | 两件事要分开跑、分开看 |
